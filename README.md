# Мотоновости: 11 источников и короткий пересказ

Бот публикует одну новость в день в Telegram: заголовок, 2–4 предложения пересказа на русском, источник, дата, ссылка на оригинал. Ежедневный запуск — GitHub Actions, около 10:00 Москвы. Публикации и повторные запуски учитываются в существующей `.bot-state/state.json`.

## Источники

В `sources.json` включены три выбранных российских раздела и восемь дополнительных источников:

| Издание | Раздел |
| --- | --- |
| MotoTeamRussia | https://mototeamrussia.com/news |
| Журнал МОТО | https://moto-magazine.ru/news/ |
| МОТОГОНКИ.РУ | https://motogonki.ru/motonews/ |
| Bennetts BikeSocial | https://www.bennetts.co.uk/bikesocial |
| Rider Magazine | https://ridermagazine.com/feed/ |
| ADV Pulse | https://www.advpulse.com/feed/ |
| Adventure Bike Rider | https://www.adventurebikerider.com/feed/ |
| Cycle News | https://www.cyclenews.com/ |
| MotoGP — официальный сайт | https://www.motogp.com/en/news/ |
| WorldSBK — официальный сайт | https://www.worldsbk.com/en/news |
| Autosport — MotoGP | https://www.autosport.com/rss/motogp/news/ |

Google News не используется. Англоязычные материалы пересказываются на русском. Для Rider Magazine, ADV Pulse, Adventure Bike Rider и Autosport читаются RSS-ленты; у российских сайтов — страницы разделов; у MotoGP и WorldSBK дата берётся из ссылки; у BikeSocial и Cycle News — из метаданных статьи datePublished. Дата изменения статьи не подменяет дату публикации.

Недоступный источник автоматически пропускается с записью в журнале, остальные продолжают работать. Пустая или сломанная RSS-лента считается ошибкой источника. При изменении вёрстки сайта может потребоваться корректировка адаптера. Если все источники недоступны, workflow завершится ошибкой. Источники опрашиваются параллельно, не более четырёх одновременно.

По тематике: BikeSocial — экипировка и гаджеты; Rider Magazine и ADV Pulse — поездки, техника и аксессуары; Adventure Bike Rider — туризм и экипировка; Cycle News, MotoGP, WorldSBK и Autosport — мотоспорт. Метка источника используется только как начальный приоритет. Окончательную тему определяет модель по тексту статьи: Мотоновости, Экипировка, Мотопутешествия, Мотогаджеты, Мировые мотособытия или Законодательство РФ.

У разных источников проверяются разные статьи: в пределах четырёх попыток бот сначала выбирает по одной статье от разных изданий, а затем дополнительные материалы. Это уменьшает доминирование одной спортивной ленты. Точные процентные квоты по темам не реализованы; предпочтительная тема чередуется по дням. Дубли одного события с разными заголовками всё ещё возможны.

Статьи с явной пометкой isAccessibleForFree=false в метаданных BikeSocial/Cycle News пропускаются. Подписки и платные API изданий не используются, ограничения доступа не обходятся. Если доступного текста меньше 500 символов, пересказ не создаётся. Доступность сайта из среды проверки и из GitHub Actions может отличаться.

Переключатель `"enabled": false` отключает источник. Не меняйте адрес одного сайта на другой без изменения адаптера: произвольные сайты не обязательно поддерживаются. Встроенная поддержка RSS сохранена для будущего подключения проверенных лент.

Материалы старше 48 часов, с неизвестной датой и повторными заголовками пропускаются. Если источник давно не обновлялся, его старые публикации не выдаются за свежие. Даты без времени считаются с начала соответствующего московского дня — проверка свежести консервативна. Событие может произойти раньше даты статьи: бот пересказывает именно свежую публикацию, а не обещает, что описанное событие случилось сегодня.

## Как делается пересказ

Бот получает статью по прямой ссылке, извлекает основной текст через Trafilatura и отправляет до 10 000 символов текста в Groq. Ключи Telegram и ID чата в запрос на пересказ не включаются. Модель возвращает русский заголовок и 55–90 слов пересказа в 2–4 предложениях. В сообщении всегда остаётся ссылка на оригинал.

Заголовок без доступного текста не пересказывается. Рекламные акции, нерелевантные материалы и тексты без содержательной информации должны отсеиваться редакционным фильтром. Фильтр и пересказ выполняются моделью, поэтому возможны ошибки — `preview` позволяет оценить результат. Достоверность каждого факта отдельной независимой проверкой не подтверждается.

Для правовых новостей есть инструкция различать законопроект и принятый закон; сообщение дополнительно помечается как сообщение СМИ. Это не мониторинг всех нормативных актов РФ: официальные правовые источники в выбранный список не входят.

Бот рассматривает до четырёх свежих неповторных материалов за запуск. Если получить текст или пересказ не удалось, он не отправляет вместо него голый заголовок. Ошибка подготовки пересказа не резервирует дневную публикацию: после исправления можно повторить запуск.

## Бесплатный ключ для пересказа

1. Откройте https://console.groq.com/keys и зарегистрируйтесь, если сервис доступен вам.
2. Оставайтесь на Free Plan; переходить на платный Developer Plan не нужно. Лимиты и доступность моделей зависят от аккаунта и могут изменяться. Бесплатность не гарантируется для платного аккаунта.
3. Создайте API key и скопируйте его.
4. В GitHub: **Settings → Secrets and variables → Actions → New repository secret**.
5. Name: `GROQ_API_KEY`. Secret: полученный ключ. Нажмите **Add secret**.

Модель по умолчанию — `openai/gpt-oss-20b`, вызываемая через Groq, не через OpenAI API. Оплаченный OpenAI API не нужен. В workflow модель задаётся переменной `GROQ_MODEL`. Если Groq недоступен в вашем регионе или модель недоступна аккаунту, пересказ не заработает до выбора доступного провайдера/модели; обход ограничений не предусмотрен.

## Обновление уже работающего репозитория

Архив обновления содержит только код и инструкцию. **Файл `.bot-state/state.json` в него специально не включён: сохраните существующую историю.** Не заменяйте её пустым начальным файлом.

1. Распакуйте архив обновления.
2. В GitHub загрузите файлы из корня обновления через **Code → Add file → Upload files**. Существующие одноимённые файлы должны быть заменены. Файлы `bot.py`, `newsroom.py`, `github_run.py`, `sources.json`, `requirements.txt` и тесты должны остаться в корне репозитория.
3. Обновите существующий `.github/workflows/moto-news.yml`: откройте его, нажмите карандаш и замените всё содержимое текстом одноимённого файла из архива. Путь и имя оставьте прежними. Так не появится лишний `moto-news.yml` в корне.
4. Сохраните изменения в `main`. Важно сначала загрузить код, затем обновить workflow.
5. Добавьте `GROQ_API_KEY`, как описано выше. Существующие `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` оставьте.
6. **Actions → Moto daily news → Run workflow → main → preview**. Откройте `publish → Find and publish one item`: в журнале должен быть готовый пересказ или причина отсутствия новости.
7. После проверки выберите `send`. Он отправит сообщение в чат из `TELEGRAM_CHAT_ID`.

Если сегодня старая версия уже отправила новость, новая отправка `send` будет пропущена — защита «одна публикация в день» продолжает действовать. `preview` позволяет посмотреть новый формат и в этот же день. Не удаляйте историю ради теста: это нарушает защиту от дублей.

На GitHub Actions новые версии служебных компонентов используют Node.js 24. Workflow устанавливает зависимости командой `python -m pip install -r requirements.txt`. Контейнер Docker также обновлён.

## Новый репозиторий

Это архив обновления, а не полный комплект для пустого репозитория. Для нового проекта дополнительно нужны `.gitignore` и начальная `.bot-state/state.json` с содержимым `{"version":1,"days":[],"articles":[]}`. Для уже работающего бота этот шаг выполнять нельзя.

GitHub бесплатно предоставляет стандартные runner для публичных репозиториев. Расписание может задерживаться или пропускаться. В публичных репозиториях после 60 дней без активности расписание может отключиться: проверяйте Actions. Для приватного репозитория учитываются квоты вашего тарифа. Автоматический повтор поиска при отсутствии новости не настроен — следующий запуск завтра или вручную.

## Диагностика и надёжность

- `preview`: настоящий подбор и вызов модели, без Telegram и изменения истории.
- `send`: настоящая отправка с сохранением дневного статуса.
- `status`: статусы последних дней, без вызова модели.
- `pending`/`uncertain`: сначала проверьте чат — сообщение могло прийти. Автоповтора в этот день нет.
- `sent`: Telegram подтвердил отправку.
- При ошибках записи истории бот не начинает отправку. Нужны права `contents: write` и разрешённая запись служебного файла в основную ветку.

Не запускайте одновременно GitHub и локальную версию для одного чата. Токены не добавляйте в код и публичные файлы. При смене чата меняйте `TELEGRAM_CHAT_ID`; дневная история сохраняется.

Локально: Python 3.11+, `python -m pip install -r requirements.txt`, секреты в `.env`, затем `python bot.py preview` или `python bot.py run`. Для постоянного локального запуска по-прежнему нужен работающий компьютер. В GitHub `.env` не требуется.

Тесты: `python -m unittest -v`. В тестах вызовы Groq и Telegram подменяются; реальный пересказ проверяется через `preview` с вашим ключом.

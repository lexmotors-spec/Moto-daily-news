# Мотоновости в Telegram — GitHub Actions

Бот выбирает одну свежую публикацию и отправляет заголовок, источник, дату и ссылку в один Telegram-чат. Работает на Python 3.11+ без сторонних Python-библиотек. По умолчанию: 10:00 Europe/Moscow, русский язык, законодательство РФ. Время меняется в `.env`, темы — в `QUERIES` файла `bot.py`.


## Бесплатный запуск через GitHub (основной вариант)

Отдельный сервер и Docker не нужны. Workflow запускается один раз в день в 07:00 UTC, то есть в 10:00 по Москве. Время запуска приблизительное: GitHub может задержать или пропустить задание. Если подходящих новостей нет, этот запуск ничего не отправляет; следующая попытка — на следующий день либо вручную. Минутный повторный поиск из разделов ниже относится только к локальному режиму `bot.py run`.

### 1. Создать репозиторий

Откройте https://github.com/new и создайте новый репозиторий `moto-news-bot`. Для стандартных GitHub-hosted runners публичные репозитории бесплатны. Приватный репозиторий использует включённую в ваш тариф квоту — проверьте Billing перед выбором. Платные API и GitHub Copilot не нужны.

Распакуйте архив. Загрузите **содержимое** папки `moto-news-bot` в корень репозитория. `bot.py`, `github_run.py`, `README.md`, папки `.github` и `.bot-state` должны быть в корне, без дополнительной вложенной папки. Файлы с точкой тоже обязательны. Не загружайте `.env`, базу из `data/` и `__pycache__`.

Удобнее всего через Git из распакованной папки:

```bash
git init -b main
git add .
git commit -m "Add daily moto news bot"
git remote add origin https://github.com/YOUR_LOGIN/moto-news-bot.git
git push -u origin main
```

Замените `YOUR_LOGIN` на свой логин; для этих команд создайте пустой репозиторий без начального README. GitHub может запросить вход. Публичный репозиторий раскрывает код и служебную историю (даты, статусы, хеши заголовков), но не токен и ID чата.

### 2. Подключить Telegram

Создайте бота через @BotFather, добавьте в чат и разрешите отправку сообщений. Токен сохраните в репозитории:

**Settings → Secrets and variables → Actions → New repository secret**

Создайте два секрета:

| Имя | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather |
| `TELEGRAM_CHAT_ID` | Числовой ID группы, включая минус |

Чтобы узнать ID, временно заполните токен в локальном `.env` (пример есть в `.env.example`), отправьте `/start@имя_бота` в группе и выполните `python bot.py chats`. Этот файл не загружайте в GitHub. Если ID уже известен, локальная настройка не требуется. `GITHUB_TOKEN` создавать не нужно: Actions выдаёт его автоматически.

### 3. Проверить и включить

Вкладка **Actions → Moto daily news → Run workflow**:

- `preview` — получить подбор в логах без отправки и изменения истории;
- `send` — отправить новость сейчас (засчитывается за текущий московский день);
- `status` — показать статусы последних дней.

Выполните сначала `preview`, затем `send` и проверьте Telegram. После загрузки workflow в основную ветку расписание включается автоматически при разрешённых Actions. Если GitHub предлагает включить Actions — включите. На других ветках workflow намеренно пропускает выполнение. Не запускайте параллельно локальный бот с тем же чатом.

Для изменения времени отредактируйте cron в `.github/workflows/moto-news.yml`: `0 7 * * *` означает 10:00 Москвы, `17 7 * * *` — 10:17 Москвы (меньше нагрузки на начало часа). `POST_TIME` из `.env` на GitHub не влияет.

### История и ошибки

`.bot-state/state.json` обновляется ботом через GitHub API. Сначала сохраняется статус `pending`, затем отправляется сообщение и сохраняется `sent`. Запись использует SHA текущей версии файла: конфликт блокирует отправку. Исчезновение/повреждение истории также останавливает запуск, без автоматического сброса.

Workflow требует `contents: write`. Если политика организации или защита основной ветки запрещает запись, публикация не начнётся. Используйте отдельный репозиторий, в котором Actions разрешена запись этого служебного файла. Не ослабляйте защиту других проектов.

`pending` или `uncertain` означает, что результат отправки надо проверить в Telegram; повтор в этот день заблокирован. Если сбой произошёл после отправки, но до сохранения `sent`, сообщение могло прийти. При таких состояниях workflow завершится ошибкой. Не удаляйте запись только ради повторного запуска без проверки чата. Для восстановления ошибки настройки исправьте Secrets/права, затем запустите снова; если дневная запись уже есть, бот её уважает.

Проверьте уведомления GitHub Actions об ошибках. В публичных репозиториях GitHub отключает расписание после 60 дней без активности — при остановке проверьте вкладку Actions и снова включите workflow. Регулярные записи состояния создают активность, но следить за работой всё равно нужно. Никаких платных runner, артефактов или кэша эта конфигурация не использует.

Документация:
- https://docs.github.com/en/actions/concepts/billing-and-usage
- https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule
- https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents

## Дополнительный вариант: локальный запуск или Docker

Ниже описан альтернативный постоянно работающий процесс. Для GitHub выполняйте инструкцию выше.

## Локальный запуск

1. Создайте бота через @BotFather в Telegram, командой `/newbot`. Полученный токен храните только в `.env` на сервере.
2. Добавьте бота в нужную группу и разрешите ему отправлять сообщения. Для канала назначьте администратором с правом публикации.
3. Скопируйте `.env.example` в `.env`, заполните `TELEGRAM_BOT_TOKEN`.
4. Отправьте в группе команду `/start@имя_вашего_бота`. Выполните `python bot.py chats` из папки проекта и перенесите ID нужной группы в `TELEGRAM_CHAT_ID` (со знаком минус). Для канала опубликуйте сообщение. Команда показывает только доступные свежие обновления; не используйте этот же токен в другом приложении или с webhook.
5. Проверьте подбор без отправки: `python bot.py preview`.
6. Запустите на постоянно работающем сервере с Docker Compose: `docker compose up -d --build`. Логи: `docker compose logs --tail=100`. Остановка: `docker compose down`.

Без Docker: `python bot.py run` на постоянно включённом компьютере с Python 3.11+, доступом к Telegram и Google News и установленной базой часовых поясов. При таком запуске процесс нужно отдельно настроить на автозапуск средствами ОС.

`python bot.py once` — немедленная настоящая публикация; она учитывается как публикация за сегодня. `python bot.py status` — состояния последних дней. Команды запускайте из папки проекта. В Docker: `docker compose exec moto-bot python bot.py status`.

## Как выбирается материал

Используется поисковая RSS-лента Google News на русском: мотоновинки, законодательство РФ, MotoGP/WorldSBK/Дакар. Источник внешнего RSS не имеет гарантии доступности и может потребовать замены. Приоритет тем чередуется по дням, затем выбирается самый свежий материал. «Интересность» здесь — простая тематическая эвристика, без редактора или ИИ. Заголовки передаются без выдуманного пересказа. Ссылка Google News ведёт к исходной публикации.

Дата публикации должна быть не старше 48 часов. При отсутствии подходящего материала бот проверяет ленты раз в минуту после времени публикации; пустых сообщений не отправляет. После простоя отправляет только за текущий день. Повторы отсеиваются по нормализованному заголовку без названия издания; разные заголовки об одном событии всё ещё могут повторяться. Для законов публикация СМИ не считается подтверждением вступления нормы в силу: в сообщении есть соответствующая пометка.

## Надёжность и ограничения

SQLite сохраняется в `data/`; не удаляйте эту папку и сохраняйте её при переносе. Запускайте один экземпляр. Дневная запись резервируется до запроса Telegram: это защищает от повторной отправки при перезапуске и неопределённом сетевом результате. Однако гарантировать строго одну успешную доставку каждый день невозможно: если Telegram не подтвердил отправку, день помечается `uncertain`, повтор автоматически не делается. Проверьте чат и логи вручную. Даже при успешном ответе Telegram сбой процесса до обновления статуса может оставить `pending`; повторов в этот день также не будет. Состояния `pending/uncertain` требуют внимания администратора.

Токен не включён в архив. Бот не запущен и не подключён к вашему чату. Нужны заполненная конфигурация и постоянно работающий сервер. Нейросетевые ключи и платные API не требуются; расходы возможны за хостинг.

Telegram Bot API: https://core.telegram.org/bots/api
